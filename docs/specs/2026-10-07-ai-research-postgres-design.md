# DSH 研究助手与 PostgreSQL

用户已授权自主长线实施，外部 API 密钥、平台登录稍后由用户配置。

## 用户行为

AI 中心有模型配置、研究对话、扫榜资料和工具技能四个入口。配置按账号持久化，浏览器只读脱敏信息。研究对话可选择作品和技能，读取作品正文、设定、人物、画布和上传资料，给出来源明确的建议。模型不能直接删除、移动、覆盖作者文件或正文。

扫榜保留榜单、来源 URL、采集时间和原始条目。采集失败、验证页面、未知结构分别报错；不伪造空榜或热度数字。公开榜单采集与作者上传/导入快照互补。技能覆盖扫榜比较、开篇分析、参考书拆解、投稿前检查、设定一致性。可连接外部 HTTP MCP，必须经 initialize、tools/list 和真实调用，分别展示配置与连通状态。

## 架构选择

采用 DSH 的核心插件组合：LLM、Session、SystemPrompt、Tools、Agent、AgentLoop。与启动完整 CLI 相比，这种组合避免给服务器用户装载 bash、任意文件系统及自修改插件；与另写 Agent Loop 相比，保留官方的工具调度和会话语义。使用本机已有源码的固定版本构建可审计的 MIT runtime bundle，记录版本、来源和许可证，不引入上游 Git。

PostgreSQL 使用账号 schema 与用户专属 schema。现有应用大量使用同步 SQLite 查询，为控制迁移范围，独立 Worker 运行 pg 连接，主线程的兼容层等待结果；每个用户进程仍独立，事务绑定同一连接，保留嵌套 savepoint。兼容层只覆盖仓库实际使用的 SQL，未知语法拒绝执行。SQLite 保留本地模式和旧数据迁移输入，服务器 Docker 默认 PostgreSQL。pgvector 安装和数据库扩展必须实测；未来接入 embedding 时必须固定模型和维度，当前不制造占位向量。

## 实施与验收

1. 数据层：先写 PostgreSQL 实库 CRUD、事务回滚、重复写入、重启和 schema 隔离测试，跑红后实现；从真实 SQLite 夹具迁移，核对行数、内容、外键、序列和重复启动。
2. DSH：用受控模型 HTTP 夹具验证真实核心 Loop 的工具请求、工具执行、最终回复、取消和预算；工具只允许显式作品范围读操作。配置和记录跨重启存在，密钥不进响应或日志。
3. 扫榜/MCP/技能：测试可识别页面、验证码/错误页、来源字段和排序；MCP 用实际协议夹具握手及调用，并探测公开来源。技能为可读 Markdown，工具集与技能说明一致。
4. 界面：按现有配色实现 AI 中心，清楚显示当前账号、作品、模型和数据来源。浏览器验证桌面/手机、配置保存、工具状态、研究对话与错误恢复。
5. 部署：独立 Novel-King Docker 栈，避免占用其他项目端口和卷；验证 PostgreSQL、pgvector、应用登录及上述业务 HTTP。完整原离线套件、语法检查和 diff 自审通过后记录结果。

## 数据与权限

现有作者数据保留原目录。迁移先复制后核对，拒绝覆盖已有目标。AI 数据和 API 配置跟随用户 schema，研究记录按作品过滤。外部 MCP 仅从管理员明确允许的 HTTPS origin 连接；不提供任意主机命令入口。API 测试夹具不调用付费模型，真实模型需要用户填密钥后验证。
