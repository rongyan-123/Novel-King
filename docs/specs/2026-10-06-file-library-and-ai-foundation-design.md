# 文件库与 AI 接入底座

## 本轮目标

把主页「参考资料」替换为直接可用的「文件库」：看数量、进入分类、自己建文件夹、批量上传、阅读、下载、删除到回收站与恢复。文件和目录由用户决定；本轮不运行自动分类、自动整理、自动写小说或榜单采集任务。

方案已获用户确认；用户授权继续细化文件分类并实施。

## 已核实的现状

- 主项目为原生 Node HTTP、SQLite 与浏览器 SPA，已有上传/作品导入、模型设置、dsh 桥接、创作工具插件和提案审批机制。
- 当前资料库是 `library_docs` 登记表 + OpenViking 原文：页面要求输入服务端磁盘目录，只接收 UTF-8 TXT/MD；服务端关闭 OpenViking 时读原文返回空文本。它不是独立的浏览器文件管理器。
- `D:/deepseek-harness` 有 package.json、node_modules 与 `apps/cli/lib/bin.js`，根目录及 CLI 包版本标记为 `0.1.0-rc.5`。现有桥接通过同级目录发现该仓库，有源码/构建产物启动选择。
- 默认用户目录下未发现 `.dsh-novel` 与其 novel profile。这不足以证明所有候选 profile 都不存在，也不足以证明模型不可用；本轮没有启动模型任务、读取或修改私人凭据。
- 当前小说插件配置保留通用 read/write/edit/glob/grep 能力，不能仅凭 HTTP 写接口拒绝，就宣称整个 Agent 对文件系统只读。

## 运行时选择

1. 推荐复用现有 dsh 桥接作为后续 Agent 的执行层，增加文件库只读工具，不把整个 dsh 源码复制到本项目。独立服务器部署时由配置指向运行时位置。
2. 短任务继续复用现有模型直连接口；文件库只依赖我们自己的服务器和数据库。文件浏览、全文搜索与下载不依赖 OpenViking、不要求配置模型。
3. 新建另一套 Agent 框架会重复处理工具、取消、运行记录和审批，目前没有足够收益。本轮不做这条路径。
4. 在之后开放资料 Agent 任务前，必须使用明确禁用通用文件写入、编辑、Shell 及管理工具的资料读取配置，并验证实际工具清单。模型指定的文件通过内部 ID 读取，不接收磁盘绝对路径。本轮只提供只读服务入口，不向 Agent 提供新上传、移动、改名、删除或恢复工具。

## 界面

- 首页侧栏为「我的书架」「文件库」「AI 中心」。AI 中心先复用现有模型配置入口，集中模型与运行时设置；高级环境诊断放到可展开区域，不引入另一套模型配置表。
- 文件库首页用分类卡片展示：世界设定、人物关系、剧情大纲、章节正文、参考书与拆书、写作技法、研究资料、榜单研究、灵感素材、投稿运营。点击卡片直接进入对应列表，不先弹抽象说明。
- 作品相关的设定、大纲、正文可选择所属作品；参考书、榜单与写作素材默认共享。所属作品显示在文件列表和详情里，与跨作品共享资料区分。
- 分类内左侧为文件夹树，右侧为文件列表，提供搜索、新建文件夹、上传文件、拖入上传。用户可以手动改名、移动与删除；未选目标分类时必须先选择上传位置。
- 文件列表显示文件名、格式、大小、所属作品、更新时间与读取状态。详情可查看内容并下载原件。与现有全局风格、深浅模式及强调色一致，手机文件夹抽屉、触控按钮和纵向列表无横向溢出。
- 全局工作概况显示真实的作品数、角色数、设定数与最近编辑章节。作品列表可查看其章节数、最近编辑标题与大纲画布节点数；不从字数或图形数猜测剧情完成百分比。
- 参考书按用户创建的「参考书资料夹」计算本数，文件另计份数。榜单资料夹可标记三江榜/新书榜，显示实际上传资料数量；本轮没有爬取器，不把手动上传伪装成已抓取书籍。
- 删除先进入回收站，可恢复；文件夹含资料时不静默递归删除。首版不提供 Agent 整理按钮或没有实际行为的 AI 功能占位。

## 文件、数据库与读取

- SQLite 保存分类、文件夹、文件元数据、所属作品、原文件名、提取文本、解析状态及回收站状态。原件保存在应用数据目录下的独立文件库目录，以内部随机 ID 定位；备份数据库和该目录即可保留原件与结构。
- 文件库独立于作品正文/结构化角色/设定表：上传到「正文」区不会直接覆盖小说章节，上传到「人物/设定」资料夹不会直接改角色卡或世界观。自动抽取并应用到作品留给后续用户确认流程。
- 首版支持 TXT、MD、DOCX、PDF、图片及其他原件上传/下载。TXT/MD 提供全文阅读与检索；DOCX/PDF 使用成熟解析库提取文本，同时保留原件。图片可预览；扫描型 PDF、旧 DOC、无法提取文本的文件显示「仅原件/无可读文本」，不把空提取结果标成 AI 已理解，不加入 OCR。
- 保留完整原件和完整提取文本，展示与只读接口分页，不为减少上下文预算而删掉正文。文件损坏或解析失败保留原件，清楚显示状态，允许重新上传或由用户删除。
- 单文件上限 20 MB，上传队列每次最多 100 个文件，以单文件请求逐个反馈成功/失败；失败文件可重试，取消上传不留下半登记记录。同名文件不覆盖，列表保留独立记录，移动文件只改元数据。
- 后端提供分类概况、目录、文件清单、上传、原件下载、分页正文、搜索、用户目录操作和回收站接口。Agent 只读端点严格验证内部 ID 和所属作品，模型侧写请求返回 403；原件位置不由模型参数决定。
- 搜索先使用 SQLite 本地全文内容匹配，能在未配置模型及 OpenViking 关闭时工作。后续向量检索可作为附加能力，不能成为原件唯一存储。
- 原有 `library_docs` 和旧资料接口保留。旧登记数据不能仅凭路径假装已迁移为新原件；迁移可用原文时才复制并确认。当前画布、章节和人物不重写。

## 实施步骤与验收

1. 建立文件/目录存储和概况接口。先写隔离数据库测试跑红，再实现：重启后原件/目录/数量不丢，所属作品隔离，旧表数据保持完整。
2. 实现原件上传、解析、下载、分页读取与搜索。先跑红：TXT/MD/DOCX/PDF 内容可读，坏文件保留原件并标记失败，20 MB 超限和路径穿越拒绝，重复文件名不覆盖，取消/失败不留下半登记。
3. 实现手动目录操作和回收站。先跑红：移动保持原件内容与 ID；删除、恢复更新计数；非空文件夹删除有明确行为；Agent 上传/移动/删除/恢复均拒绝，只读不会改变目录与原件。
4. 重做文件库仪表盘、列表、文件夹树、上传队列与详情，收敛 AI 中心入口。用真实浏览器验证点卡片进入、批量选择/拖入、阅读、搜索、移动、误传删除、恢复及刷新后保留。
5. 验证桌面与 390px 手机、深浅模式和既有风格，检查截图；运行完整离线检查、构建/语法检查和 diff 自审。浏览器与 HTTP 测试仅使用隔离数据目录，不写作者数据库、不调用付费模型。

## 后续 AI 接入顺序

文件库完成后，先核对 dsh 实际运行配置和只读工具，再接「选资料讨论剧情/检查设定/生成候选大纲」；给出可定位的文件引用和提案，让用户确认后才写入小说或画布。扫榜与拆书在有独立采集来源、保存原始记录和可查看任务结果后再加入，不用虚构数据填仪表盘。
