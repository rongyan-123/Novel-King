# Agent 聊天首页与页面加载修复

用户已授权按截图方向一路完成。范围包括冷启动空白、导航旧内容残留、默认 AI 聊天首页、持久化会话，以及 DSH 自主扫榜和编辑视角分析。保留现有账号、额度、上游配置和持久化卷。

## 实施与验证

1. 启动即显示加载状态，独立脚本并行下载；AI 策略读取不阻塞首屏。切页先替换页面容器，旧请求只能写入已脱离文档的容器。验证：延迟请求回归测试、实际限速浏览器与快速来回切页。
2. 在每个用户独立数据库 schema 新增 conversations/messages。作品范围固定在会话上，多轮消息、失败、取消、进程中断均可恢复，保持每用户一次研究任务。验证：SQLite/PG 存储、越界读取、重启与并发测试。
3. 继续使用现有 DSH 核心，通过原生消息历史恢复上下文，输出安全的文本流和工具活动；工具与技能统一提供给 Agent，自主选择。外部 MCP 故障单独提示，保留内置工具。验证：真实 DSH 循环配确定性模型服务、工具选择、跨轮上下文、脱敏、取消。
4. 首页为 AI 中心，左侧会话、中央对话、底部输入和当前小说/模型，榜单、模型、MCP 与技能配置收在设置入口。书架、文件库、写作台保留。验证：桌面和手机聊天、切会话、设置、导航与保存回归。
5. 原创编辑技能优先评估题材组合、目标读者、可持续故事引擎、市场样本与差异化，再看开篇与文笔；允许明确建议重写，必须标明来源、日期、缺失证据与判断依据。榜单简介不能冒充读过全文。验证：技能契约、带样本和本书证据的完整演示。
6. 回归测试、自审 diff 后先备份再更新 Linux 的应用镜像，保留资源上限、域名、数据库和文件卷。验证：公网登录、会话持久化、桌面/移动端浏览器与资源监测。

## 真实验收边界

当前 owner 无小说、平台无上游。用户选择用明确标注的演示稿验收，之后自己填写上游 Key。确定性演示须标明模型为测试服务；真实起点采集另行验证，不能称为真实模型对用户小说的结论。AI 读取和建议，不自动删除、移动或覆盖作者稿件。
