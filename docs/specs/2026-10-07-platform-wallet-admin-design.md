# Novel-King 平台模型、人民币额度与管理员后台

用户已确认按 MapFlow 最新主线移植，并追加管理员界面及持久化上游 API Key 管理。参考前端 main a753d77、后端 main f9a9b7c；参考项目只读，独立账本，不读取其私有密钥。

## 用户行为与范围

平台调用按可信上游人民币实扣的两倍结算，金额以整数微元保存，一元等于一百万微元；新账户首次初始化赠送十万微元（0.10 元）。自填 Key 保留个人数据库持久化和原有调用方式，不扣平台余额。

平台模型目录沿用 MapFlow 的九个模型及各自参数白名单。价格与渠道统计由账户服务使用管理员配置的 Key 读取，只展示公开字段；未配置、不可用、未知统计明确显示。连接测试仅查询模型列表，不发送收费聊天请求。

用户入口包含余额、充值、历史流水、模型价格。管理员入口包含概览、用户搜索/停用/恢复/重置密码、上游 Key 新建/替换/停用/切换、模型配置、收款码、充值审核、额度调整和冲正、请求观测、审计、邀请码、公告、反馈。MapFlow 的公共树审核对应其特有的公共地图发布功能，Novel-King 不存在公共小说发布，故不虚构审核对象。

微信及支付宝充值支持人工确认与可配置的 VMQ 自动到账。沿用订单幂等、签名校验、反查已付款订单、金额核对、实际支付金额到账与二十秒收款码展示队列。未配置 VMQ 时使用人工审核。该适配只访问 Novel-King 配置的支付服务，不修改 MapFlow 的支付服务与订单。

## 架构

账户服务管理共享账户钱包、预留、账单、管理员配置。既有个人 worker 继续持有作品、画布和资料库。平台模型通过认证的进程内网关调用，网关从 worker 身份确定用户，不信任请求上报用户或费用。平台 Key 不下发给个人 worker 或浏览器。个人模型配置继续独立。

平台配置以受保护的模型配置记录出现在既有编辑器和 DSH 模型选择中；复用同一中转入口覆盖正文、润色、画布和 DSH 的所有模型轮次。每轮调用单独预留和结算，因此已成功的研究轮次不因后续停止而退还；未完成轮次释放预留。消费记录按账户和模型调用展示。

上游 Key 使用服务器私有主密钥 AES-GCM 加密后持久化；浏览器只能读取是否已配置及掩码。管理员敏感写操作校验当前密码并记录不含密钥的审计记录。备份数据库时必须一起保管私有主密钥。

## 金额与失败处理

报价使用当前有效渠道的最高输入/输出价、实际请求大小及输出上限计算保守预留。报价绑定账户、请求内容及模型。钱包数据库事务锁保证并发请求、充值、管理员调整不能消耗已预留资金。可信费用异常高于预留上限时扣费封顶，记录差额。

费用帧与 token 帧分开解析；只有费用的尾帧不得覆盖 token 统计。缺失费用、错误币种、断流、冲突费用、负数或异常格式一律失败，不猜测费用。成功结果先持久化账单再返回；幂等重试重放结果，不重复调用上游。进程失效恢复先阻止迟到响应结算，再释放预留。

## 实施步骤与测试边界

1. 金额与模型目录：公开转换、参数校验边界；先红后绿验证精度、舍入、无效值及模型参数。
2. 钱包与管理员存储：公开钱包/订单/预留/结算/调整接口；先红后绿验证一次赠送、隔离、幂等、并发、封顶、失败释放、冲正、Key 脱敏及重启持久化。
3. 模型与支付适配：HTTP 边界；假上游验证真实字段、费用尾帧、定价缓存、无收费探测、支付签名和订单匹配。
4. 账户网关与 worker 接入：实际认证 HTTP 边界；验证普通用户无法管理、匿名拒绝、个人资料隔离、所有平台模型入口计费、BYOK 不扣费。
5. 用户钱包与后台界面：浏览器交互；桌面/手机实测用户查询、Key 管理、充值及额度调整，全局主题一致。
6. 完成前完整现有测试、真实隔离 PostgreSQL 测试、语法检查及 diff 自审；不使用生产钱包或实际付费模型做自动化测试。
