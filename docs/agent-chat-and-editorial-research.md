# Agent 聊天与编辑研究

2026-10-07：AI 中心作为首页和侧栏第一项，左侧保存会话，中央显示回答，底部选择小说与模型。书架、文件库与写作台继续使用原来的作者数据。模型、工具与技能、榜单资料集中在聊天右上角的「AI 设置」。

## 使用

1. 管理员在账户菜单的管理后台配置上游地址、API Key 和可用模型。平台额度与模型接入沿用现有系统；也可在「AI 设置 → 模型配置」保存个人模型配置。密钥持久化到原有数据库，不写入源码。
2. 上传正文、大纲、人物和设定到对应小说的文件库，或直接在书架写正文。在聊天底部选择这本小说。仅选择「共享资料与榜单」时，Agent 不能读取某本未选小说的私有资料。
3. 输入「根据起点榜单，研究一下我的小说」。DSH 自主选择技能、榜单和资料工具；展开回答下的「查看过程」能看见实际调用和失败状态。可连续追问或停止回答。
4. 右上角「AI 设置 → 工具与技能」配置只读 HTTP MCP，并显式选择允许的工具。外部 MCP 连接失败会提示原因，内置作品、文件和榜单工具仍可用。

会话绑定创建时选择的小说。切换小说会开始新会话，避免混用两部作品的上下文。聊天自动保存，刷新后恢复；失败或停止时保留收到的回答，服务重启不自动继续收费调用。删除会话只删除聊天记录，不删除小说或资料。

## 分析顺序与证据

继续使用项目已引入的 DSH 0.1.0-rc.5 原生 Agent 循环，提供模型可自主选择的工具，而不是用关键词固定分支冒充 Agent。会话恢复使用原生用户/助手消息历史。内置工具可读取当前小说目录、章节、人物设定、卷纲与剧情线、大纲画布、个人共享资料及选中小说的文件，以及带日期的榜单快照。

新增两份原创技能：

- `editorial-review`：先判断题材成分、读者承诺、相关榜单样本、故事引擎和整体架构，再看开篇与文笔。允许明确建议重构或重写，并说明证据、代价、原创替代路线及改后验收标准。
- `comparable-dissection`：按实际读到的证据层级拆解参考书，再对比作者作品。书目或简介不能支持「已拆解全书」的结论；开篇与全文分析需要可用的公开文本或作者上传资料。

结论必须区别事实、分析和待验证假设，引用章节/文档 ID、来源 URL、采集日期与已读范围。没有依据的分数、签约概率、编辑原话和拒稿原因不能编造。AI 只读取资料、给建议和改写示例，不自动覆盖、移动或删除作者内容。

技能调研参考 [webnovel-writer](https://github.com/lingfengQAQ/webnovel-writer) 的一致性评审与定位范围、[long-novelist-skill](https://github.com/tianshiemo7/long-novelist-skill) 的创作流程，并核对 [阅文官方帮助中心](https://help.yuewen.com/help?siteId=2) 的审核与签约问题。本项目没有复制第三方技能正文；上述工具不能代表平台实时签约标准。未获许可的第三方技能未引入。

## 榜单读取与限制

内置起点采集支持签约新书、潜力、未签约新书、月票、畅销、推荐、三江；读取公开书目、作者、类型、简介和来源时间。三江按页面最新显示的推荐期保存。采集串行执行，间隔至少 10 秒；没有取得书目时不保存空快照。

本次正式网络检查遇到起点验证码，返回「尝试太多了2s后自动为您刷新验证码」，没有取得可用于实时分析的榜单数据。程序明确显示需要访问验证，保留在浏览器查看后手动导入快照的方式。已有快照必须标明日期，不能冒充当前榜单；本次没有绕过验证码。

每用户同时一个 AI 研究任务，与旧研究入口共享限制。单次最多 18 步、5 分钟；问题最多 12000 字，持久化回答最多 128000 字，工具活动最多 32 KiB/96 项。每会话最多 100 轮；发送模型的历史限定最近 30 条完整消息、合计 50000 字。现有服务器最多两个用户写作进程；榜单浏览器继续全局单任务运行。

- 发布前完整离线检查 61 组通过；隔离 API 检查 191 项通过、0 失败，4 项会写全局 OpenViking 的检查按隔离策略跳过；原小说写作 smoke 39 项通过。
- 实际 PostgreSQL 10 项检查通过，覆盖会话事务、重启恢复、账户隔离、存储和平台额度；使用独立测试 schema，未改作者数据库。
- browser-harness 在真实 Chromium 验证桌面、390 px 手机、会话恢复、连续追问、停止、设置、快速切页、深色界面及限速冷启动。启动和切页显示状态，旧页面请求不能覆盖新页面；无页面脚本错误。
- 按用户选择，用「【演示稿】镜城的账本」与明确标注的受控测试模型完成真实 DSH 九次自主工具调用。演示中起点采集失败如实标记；模拟书单单独标注，继续读取本书正文和上传总纲，并验证追问、停止和持久化。它验证工具循环和界面，不代表付费模型效果、当前市场判断或真实签约建议。

演示环境与生产数据库隔离，正式 owner 账号不安装模拟模型、演示稿或模拟榜单。生产平台尚无上游 Key，用户稍后自行填写。截图、日志和私有验收数据保存在已被 Git 忽略的 `accounts-data/server-deployment/`。

沿用 Linux 的 `novelking` Compose 项目与 PostgreSQL、文件、证书卷。发布前完整备份在 `/opt/novel-king/backups/public-20261007_165052/`，数据库 dump、上传原件、平台主密钥、证书、配置和源码 bundle 共 16 项校验通过。只更新应用镜像，资源上限和其他服务保持原配置。

具体入口与迁移说明见 [Linux 部署记录](linux-laptop-deployment-2026-10-07.md)。应用、PostgreSQL、榜单浏览器、HTTPS 网关的 Docker 内存上限合计 2912 MiB；加上两项原生网络服务为 3008 MiB。恢复时数据库与文件/主密钥必须成对恢复，不删除原有卷。

已部署应用镜像 `novelking-app:70e1f9e`。公网原账号、14 个原有接口、桌面/手机交互及限速启动验收通过；新增空会话也经真实 PostgreSQL 查询确认落盘，验收后已删除。临时演示容器、专用浏览器和转发已停止并清理。
