# 平台模型、额度与管理后台

登录管理员账号，点击右上角 **管理后台**。在写作台也有相同入口。普通账号只显示 **额度**，后台接口会独立验证管理员身份。

## 配置上游 API Key

1. 打开 **上游 API Key → 添加上游 Key**。
2. 填写名称、接口地址及 Key；默认接口为 `https://anyai.token6688.com/v1`。
3. 输入当前管理员密码并保存。第一个启用的配置自动成为当前上游。
4. 使用 **测试当前连接** 验证模型列表。该测试不发送收费生成请求。

可保存多个 Key，替换、停用、恢复，并指定当前上游。配置持久化到共享账户数据库；Key 通过 AES-256-GCM 加密，浏览器只能看到末四位。真实上游 Key 不下发给用户的作品进程。

**概览**与**上游 API Key**页面显示当前上游的账户可用余额、币种和查询时间，支持“刷新余额”。查询使用与 MapFlow 相同的 `GET /v1/skills/balance`，不发起收费生成请求；常规读取缓存 60 秒，更换 Key 后立即重新查询。上游返回美元时显示美元，不擅自换算为人民币，也不把同一账户的多个 Key 重复相加。未配置、不支持、权限不足及连接失败会显示具体状态，不当作零余额。此接口只对管理员开放。

平台计费需要上游提供 AnyAI/MapFlow 的渠道定价接口，以及 SSE `usage.cost_rmb` 和 `usage.cost_currency: "CNY"` 回执。仅提供标准 OpenAI 聊天接口的服务，应作为个人 Key 配置使用；不能据此推算平台账单。

当前模型目录与参数白名单采用本次参考的 MapFlow 主线。管理员可在 **模型设置** 开放或停用模型。用户在 **额度 → 模型价格** 查看当前渠道单价和统计，并保存自己的思考、联网等模型参数；未知统计不虚构数值。

## 使用与计费

AI 中心、正文及大纲画布、DSH 研究共用现有模型选择器；名字以 **平台 ·** 开头的配置使用平台额度。个人 API Key 仍保存在个人数据库，使用个人上游余额，不扣平台额度。

- 首次初始化账户赠送 **¥0.10**，已有账户也只补发一次。
- 成功调用按上游实际人民币费用的 **两倍**结算，金额以整数微元保存。
- 与 MapFlow 当前规则一致：个人平台余额为正即可发起，不要求覆盖最贵渠道的最大预估。调用期间锁定现有余额，每个账户同时处理一个平台模型调用；未完成、取消、异常账单会释放锁定。
- 完成后按完整实际账单结算，即使本次费用超过余额也保留准确欠费；余额不大于零时阻止下一次调用，补足后继续。管理员填入上游 Key 不会自动增加个人平台额度。
- 研究任务按每次成功模型轮次扣费；之后停止研究不会撤销此前已完成轮次。
- 幂等请求会重放已保存结果，不重复调用和扣费。升级前的预付账单保留原有封顶语义，新调用不再以预估金额截断真实费用。
- 本版先收齐模型输出、用量和账单并持久化结算，再把结果交给编辑器。因此平台模式在生成期间等待完整结果，暂不逐 token 实时展示；个人 Key 的原有流式行为保留。

用户可查看自己的消费、充值和资金流水。管理员的请求观测展示状态、token 和费用，不展示用户提交的小说正文或模型提示词。共享数据库保存账单和用于幂等重放的模型结果。

## 充值

默认人工审核。在 **收款码** 上传或拖入微信、支付宝 PNG/JPEG 图片；每笔订单保留创建时的收款码。

用户创建订单后加入二维码队列。按先后顺序，每次显示 20 秒；用户之间不能读取对方订单或二维码窗口。“我已付款”只提交待审核状态。管理员在 **充值审核** 核对实际收款，填写唯一凭证编号后入账。相同订单或凭证不会重复入账。

可选 VMQ 自动充值：准备私有 JSON，放入持久化数据卷的 `private/vmq.json`，并设置 `.env`：

```dotenv
NOVELKING_VMQ_CONFIG_FILE=/var/lib/novel-king/private/vmq.json
```

文件格式：

```json
{
  "baseUrl": "https://payment.example.com",
  "key": "replace-with-your-payment-key",
  "notifyUrl": "https://novel.example.com/api/platform/vmq/notify",
  "returnUrl": "https://novel.example.com/"
}
```

私有文件需由容器中的 `node` 用户读取，不提交 Git。更新环境变量后重建应用容器。VMQ 通知必须通过签名、本站订单匹配和支付服务的已付款订单反查；余额按实际支付金额到账，包括有效零头。本站使用独立商户参数 `novelking-v1`，不会把 MapFlow 订单计入本站。

## 后台分区

| 分区 | 功能 |
| --- | --- |
| 概览 | 当前上游可用余额、用户数、可用账号、待审核充值、平台调用及资金汇总 |
| 用户管理 | 搜索、余额和消费统计、停用、恢复、重置密码 |
| 上游 API Key | 当前上游可用余额、加密保存多个 Key、替换、启停、切换、免费连接测试 |
| 模型设置 | 平台模型白名单 |
| 充值审核 / 收款码 | 收款图片、人工审核、可选 VMQ 自动到账 |
| 额度调整 / 资金流水 | 增减额度、说明、冲正；保留原始流水 |
| 请求观测 / 审计日志 | 调用状态及敏感管理操作记录 |
| 邀请码 | 创建、次数限制、撤销；可切换注册是否需要邀请码 |
| 公告 / 用户反馈 | 发布、收起公告；查看及回复反馈 |

管理员敏感写操作需要当前密码。账号停用和重置密码会结束其现有登录。后台使用 Novel-King 全局主题，手机侧边栏转为可横向滑动的分区导航，表格在自己的区域内滚动。

## 持久化与部署

沿用 `compose.yaml` 的 PostgreSQL 与两个数据卷。账户和平台账本在共享账户 schema，作品仍在各用户独立 schema。平台不迁移或复用 MapFlow 的用户、钱包及私有 Key。

备份必须同时保存 PostgreSQL 和应用数据卷内 **`private/platform-master.key`**；只恢复数据库不能解密上游 Key。VMQ 私有配置也位于应用数据卷。个人数据库与原作品迁移方式见 [账户与部署](accounts-and-deployment.md)。

账户网关采用单实例，个人作品进程继续按用户分隔。PostgreSQL 会拒绝第二个同时连接同一账户 schema 的网关，避免重复启动误释放正在执行的资金预留；重启时释放尚未结算的预留。

2026-10-07 计费修正：原实现按最贵渠道预估预留，可超过新账户体验额度并在调用上游前返回 402。现采用完成后结算，并使用 OpenAI 兼容的错误结构，让 DSH 显示“个人平台额度不足”或“上游账户余额不足”的具体原因。升级自动扩展钱包金额约束以保存欠费，保持原账户、流水、Key 和账单。平台模型在作品进程启动时按平台目录修复，不再沿用个人 DeepSeek 配置的历史名称改写。
